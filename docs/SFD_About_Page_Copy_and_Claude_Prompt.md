## Claude Implementation Prompt

```text
You are working inside the existing SynergyFirst Digital website repository.

Your task is to design and implement the complete `/about/` page using the approved copy supplied below. Do not merely place the text into generic stacked sections. Create a polished, premium, conversion-focused About page that feels consistent with the current website and supports the overall sales journey.

PROJECT CONTEXT
- Brand: SynergyFirst Digital
- Audience: Local and service-based businesses in the USA, Canada, Australia, New Zealand, Germany and other European markets
- Core services: Website design and development, local SEO, WordPress maintenance, digital marketing, social media, automation and custom digital solutions
- Positioning: An experienced, practical digital partner for local businesses—not a generic design agency
- Tech: Existing Astro project with CSS/JavaScript and page content stored in JSON under the project-root `/data` directory
- Theme direction: Premium light theme, modern editorial layout, strong typography, thoughtful whitespace and selective use of the existing brand accent colors
- Existing global header, navigation, footer, buttons, typography, spacing tokens and design system must remain consistent

REFERENCE
- Structural inspiration only: https://icreateyoursite.com/about/
- Do not copy its wording, branding, layouts or assets.
- Do not implement its “Meet the Team” section.
- Improve on the reference with stronger buyer relevance, industry fit, differentiation, work proof, founder credibility and SEO-focused FAQs.

FIRST: AUDIT BEFORE EDITING
1. Inspect the current repository structure and existing About page, if present.
2. Inspect the homepage, Services, Industries, Our Work and How It Works pages to understand reusable components, URL patterns and visual language.
3. Find the current data schema and naming convention used for page-level JSON.
4. Reuse existing components wherever suitable. Create new reusable components only when there is a clear need.
5. Do not change unrelated pages or global styles unless a small, reusable improvement is necessary. Explain any such change in the final summary.

CONTENT ARCHITECTURE
Create or update the page data in `/data/about.json` following the project's established JSON pattern. Do not hardcode page copy inside Astro components unless the existing architecture explicitly requires it.

Render these sections in this exact strategic order:
1. Hero
2. Why We Exist
3. Our Story
4. What We Help Businesses Achieve
5. What Makes Us Different
6. Industries We Understand
7. How We Work
8. Selected Work / Proof
9. Founder Note
10. FAQ
11. Final CTA

VISUAL DIRECTION
- The hero should feel confident and spacious, with an editorial composition rather than a standard centered template.
- Use a relevant existing brand image, founder image or abstract digital visual only if it supports credibility. Do not use random stock-office imagery.
- Create visual rhythm by alternating restrained full-width sections, split layouts and card/grid sections.
- Service cards should be concise and link to the relevant service pages when valid routes exist.
- Industry cards should link to real industry pages. If a route does not exist, do not create a dead link.
- The four-step approach should feel like a connected progression on desktop and a clean vertical sequence on mobile.
- Selected Work must reuse two or three real portfolio projects from the existing data source.
- The founder note should feel personal and editorial, not like a team member card.
- FAQs should use an accessible accordion only if the site already has an established accordion pattern; otherwise use a simple semantic disclosure component.
- Motion must be subtle and purposeful. Respect `prefers-reduced-motion`. Avoid scroll-jacking, parallax overload, excessive floating effects and entrance animations on every element.

RESPONSIVE AND ACCESSIBILITY REQUIREMENTS
- Mobile-first and fully responsive at all existing breakpoints.
- Maintain readable line lengths and strong spacing on small screens.
- Semantic HTML with one H1 and logical H2/H3 hierarchy.
- Full keyboard accessibility and visible focus states.
- Meet WCAG AA contrast.
- Add meaningful alt text for informative images and empty alt text for purely decorative images.
- Buttons and links must have clear, descriptive accessible names.

SEO REQUIREMENTS
- URL: `/about/`
- SEO title: `About SynergyFirst Digital | Web Design & Growth Agency`
- Meta description: `Meet SynergyFirst Digital, the web design and digital growth agency helping local businesses attract customers through websites, local SEO and automation.`
- Canonical URL should follow the project's current canonical pattern.
- Add Open Graph and Twitter metadata using the existing SEO component.
- Add appropriate JSON-LD using only verified information: `AboutPage`, `Organization`, `BreadcrumbList` and `FAQPage` where compatible with the current schema setup.
- Do not keyword-stuff headings or body copy.
- Ensure all internal links use the site's clean trailing-slash URL convention.

CONTENT INTEGRITY RULES
- Use the approved copy exactly, allowing only tiny grammatical adjustments required by the component context.
- Do not invent awards, badges, review scores, client logos, customer counts, project counts, office locations, revenue results or performance percentages.
- “25+ years” refers to hands-on web experience, not necessarily the age of SynergyFirst Digital. Keep that distinction intact.
- Use only verified portfolio items, testimonials and images already present in the repository.
- Do not mention Indian pricing, INR or the Indian market. This page is written for international buyers.
- Do not add a Meet the Team section.

PERFORMANCE REQUIREMENTS
- Preserve or improve Core Web Vitals.
- Use Astro image optimization or the project's established image component.
- Set image dimensions to prevent layout shift.
- Lazy-load below-the-fold media.
- Avoid adding a large client-side library for a minor interaction.
- Keep the rendered page functional if JavaScript is unavailable, except for optional enhancement behavior.

APPROVED COPY

1. Run the existing build, type-check, lint and test commands available in the repository.
2. Fix every error caused by this work.
3. Check the rendered page at desktop, tablet and mobile widths.
4. Verify that there is no horizontal overflow, clipped text, broken card layout or awkward heading wrap.

FINAL RESPONSE
```
